# Reference records

## Key takeaway
A local Reference identifies an external publication and exactly what it contributes; it is not the source itself or proof of its claims.

## Summary
Only Markdown records are stored here. A record includes publication identity, date basis, external address, inspected extent, located claims, evidence lineage and nonclaims. Naming uses creator, publication year when known, and a concise title. An access year never masquerades as publication year. Several records may describe one evidence family or implementation chain.

## How to use a record
Read the local Summary and claim contribution, then examine the scope and what the source does not establish. A claim-specific locator tells you where to inspect the external source. If only an abstract was accessible, do not infer full methods, raw data or unreported outcomes. Place KPS-specific application synthesis in the relevant Practice rather than rewriting the publication's contribution.

## Evidence and edition differences
This package has one practical Markdown edition. Earlier source inspection notes remain historical metadata; each record states what was actually inspected and when. New inspection and retained scientific inspection history are separated in SOURCE-REVIEW.md. Official documentation describes a product's interface; it is not a test of KPS efficacy.
