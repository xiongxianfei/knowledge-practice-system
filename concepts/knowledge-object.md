# Knowledge object

## Key takeaway

An object earns a file through a coherent independent use, not merely by being a sentence.

## Summary

A knowledge object is a named unit whose content can be understood, referenced and revised coherently. Its stable identifier tracks identity, its title helps people find it, and its primary role determines its folder. File length alone is not a classification rule.

## Definition and use

A coherent, reusable unit with a stable identity, a primary knowledge role and sufficient context for correct use.

A reusable explanation of representation drift can support several workflows. One project’s failed link is an application observation. A local stage explanation may stay in the Practice until independent reuse makes a separate object worthwhile.

## Boundary and non example

One statement may serve several roles, but choose the file’s main purpose and place context-specific details where they are used. Do not create near-duplicates merely to fill categories.

## Local evidence and uncertainty

This file uses KPS’s declared conventions or an explicit reasoning argument rather than claiming an externally tested intervention. Its explanation and counterexample are local; linked objects identify reusable connections, not independent confirmation.
